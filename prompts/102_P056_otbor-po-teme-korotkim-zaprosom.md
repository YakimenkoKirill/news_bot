## Задача

Сейчас один запрос возвращает и оценку, и полный пересказ — даже для новостей «не по теме», которых большинство. Выходные токены в 4 раза дороже входных, а пересказ — основная их часть.

1. **Промпт отбора** (app/pipeline/ai/prompts.py): `build_screen_messages(news, profile, max_chars)` — системное сообщение с темой канала и правилами оценки (то же определение relevant и score, что сейчас), ответ — JSON ровно с ключами `relevant` и `score`. В пользовательском сообщении — заголовок и первые ai.screen_input_chars символов текста (truncate_words). Системное сообщение не содержит меняющихся данных (дат и т. п.), чтобы срабатывал кэш провайдера.
2. **Промпт пересказа:** из RESPONSE_KEYS и системного сообщения убираются relevant и score — их решает отбор. PROMPT_VERSION -> "v4".
3. **Схема** (app/pipeline/ai/schema.py): `parse_screen_response` (relevant: bool, score: float 0..1) и обновлённый разбор пересказа без relevant/score.
4. **AiProcessor.process:**
   - отбор: `chat_json(screen_messages, max_tokens=ai.screen_max_tokens)`, один повтор при плохом ответе; AiRequest kind = screen; дважды плохо -> failed / bad_ai_response;
   - не по теме или score < ai.min_score -> filtered / not_relevant, пересказ не запрашивается, ProcessedPost не создаётся;
   - иначе пересказ как раньше (AiRequest kind = summary); score в ProcessedPost.relevance_score — из отбора;
   - проверка фактов, модерация, лимит источника — без изменений.
5. **Отключение:** `ai.two_stage: true`. При false — прежний один запрос с прежним промптом v3 (сохрани его как отдельную функцию, чтобы можно было откатиться без деплоя старой версии).
6. **Отчёт:** в блоке «Модель» — «отбор: {N} запросов, ${X}; пересказ: {M}, ${Y}» по kind из ai_requests.

**Критерий готовности:** Для новостей не по теме оплачивается только короткий запрос отбора; итоговые статусы и качество пересказов прежние.

**Граничные случаи:** Отбор вернул score ровно min_score -> проходит (как сейчас: < min_score отсеивается); отбор ок, пересказ дважды плохой -> failed, оба запроса в ai_requests; two_stage = false -> поведение и промпт как до шага; бюджет исчерпан между отбором и пересказом -> пересказ не запрашивается, новость остаётся normalized (как при исчерпании перед новостью) — проверь, что BudgetExceeded не теряет запись AiRequest отбора; ответ отбора с лишними ключами -> плохой ответ.

**Тесты:** `tests/unit/test_prompts.py` — состав промпта отбора, отсутствие изменяемых данных в системном сообщении, усечение текста, v4; `tests/unit/test_ai_schema.py` — разбор ответа отбора; `tests/unit/test_ai_processor.py` — все ветки: не по теме (один запрос), по теме (два запроса), плохой ответ отбора, плохой ответ пересказа, two_stage = false; `tests/unit/test_daily_format.py` — строка отбор/пересказ. Обнови тесты прежнего промпта только в части удалённых ключей.
