## Задача

Сейчас Deduplicator.check (app/pipeline/dedup.py) для каждой новости вызывает recent_simhashes — все SimHash за dedup.window_h (48 ч) без подходящего индекса — и считает расстояние в Python. На пачку из 20 новостей это 20 полных выборок.

Принцип: 64-битный SimHash делится на 4 части по 16 бит. Если расстояние Хэмминга ≤ 3, хотя бы одна из 4 частей совпадает точно (принцип Дирихле). Поэтому кандидатов можно искать по индексу на точное совпадение любой части, а точное расстояние считать только для них.

1. **Миграция 0006** (down_revision "0005"): столбцы news_items.simhash_b0 … simhash_b3 (Integer, NULL), индексы `ix_news_items_simhash_b{N}_created_at` по (simhash_bN, created_at); заполнение для существующих строк SQL-выражением из simhash (с учётом хранения знакового bigint через to_db/from_db: части считай от беззнакового значения).
2. **Функция** `simhash_bands(value: int) -> tuple[int, int, int, int]` в dedup.py.
3. **Запись:** при сохранении simhash (update_fields в нормализации) записываются и 4 части.
4. **Поиск:** `NewsRepository.simhash_candidates(bands, since) -> list[tuple[int, int, int | None]]` — `WHERE created_at >= since AND (b0 = :b0 OR b1 = :b1 OR b2 = :b2 OR b3 = :b3)`; Deduplicator.check использует его вместо recent_simhashes, точное расстояние — как раньше.
5. **Ограничение:** метод корректен только при dedup.simhash_max_distance ≤ 3. Валидатор DedupConfig: при значении ≥ 4 — ошибка конфигурации с объяснением (или, если хочешь сохранить гибкость, откат на recent_simhashes с предупреждением в логе — выбери одно и опиши в docstring).
6. recent_simhashes оставь только если он ещё где-то нужен (scripts/eval_dedup.py); иначе удали вместе с тестами, которые проверяли только его.

**Критерий готовности:** На тех же данных найдены те же дубли, что и раньше (проверь на размеченном наборе tests/fixtures, если он есть), а запрос кандидатов использует индексы (EXPLAIN в интеграционном тесте не содержит Seq Scan по news_items при включённом enable_seqscan = off).

**Граничные случаи:** Отрицательные значения simhash в БД (знаковое хранение) -> части считаются верно; расстояние ровно 3 в разных частях -> найдено; расстояние 4 -> не найдено (как и раньше при пороге 3); новость без simhash -> части NULL, в поиске не участвует; новости вне окна -> не кандидаты.

**Тесты:** `tests/unit/test_simhash.py` — simhash_bands, свойство «расстояние ≤ 3 => совпадает часть» на случайных парах (фиксированный seed); `tests/unit/test_deduplicator.py` — Deduplicator на fake-репозитории; `tests/integration/test_repo_simhash.py` — кандидаты, окно, отрицательные значения, EXPLAIN; `tests/integration/test_migrations.py` — 0006 и заполнение существующих строк; `tests/unit/test_config.py` — валидатор.
