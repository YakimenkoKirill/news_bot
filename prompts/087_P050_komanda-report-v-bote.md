# Шаг 087 из 088 · P050 · Этап 13 — Ежедневный отчёт в боте управления

**Задача трекера:** Ежедневный отчёт: доставка в бот
**Результат:** Команда /report с выбором периода: сегодня, вчера, 7 дней
**Коммит:** `feat(bot): команда /report — отчёт за день`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/087_P050_komanda-report-v-bote.md». После коммита: `python prompts/next_step.py --done`.

## Задача

1. **Сервис отчёта** app/reports/service.py — общий для команды и для ежедневной отправки (шаг 088):
   - `ReportPeriod(StrEnum)`: `today` (с 00:00 до текущего момента), `yesterday` (вчерашние сутки), `week` (последние 7 полных суток, не включая сегодня). Для каждого — предыдущий период той же длины для сравнения.
   - `periods(kind, now, tz) -> tuple[Period, Period, str]` — период, предыдущий период и заголовок («14 октября», «вчера, 13 октября», «7–13 октября»).
   - `@dataclass(frozen=True) ReportDeps`: session_scope, ctx-фабрика DailyContext, cfg (DailyReportConfig), metrics (MetricsConfig), text_limit, tz, clock.
   - `async build_report(kind: ReportPeriod, deps) -> list[str]` — collect_daily + format_daily (шаги 085–086) в одной транзакции только на чтение.
2. **Клавиатура** (app/bot/keyboards.py): `ReportAction(CallbackData, prefix="rp")` с полем period; `report_keyboard(current)` — «Сегодня» / «Вчера» / «7 дней», текущий помечен «•».
3. **Обработчик** app/bot/handlers/report.py:
   - `/report` -> отчёт за сегодня; клавиатура выбора периода под последним сообщением отчёта.
   - Кнопка периода -> `callback.answer(«Считаю…»)` сразу (отчёт за неделю может считаться дольше, чем Telegram ждёт ответа на кнопку), затем отчёт новыми сообщениями.
   - Ошибка подсчёта (например, БД недоступна) -> лог `report.failed` и сообщение «Не удалось собрать отчёт, подробности в /errors», без падения обработчика; события в журнал ошибок обработчик сам не пишет.
   - `create_router()` регистрирует /report и `ReportAction.filter()`.
   - `ReportDeps` берётся из workflow_data по ключу `report_deps`.

**Критерий готовности:** Админ в любой момент получает /report за сегодня, вчера или неделю; отчёт за неделю считается тем же кодом, что и за день.

**Граничные случаи:** /report в 00:05 -> «сегодня» почти пустой, это нормально; неделя через смену месяца («28 сентября – 4 октября»); несколько сообщений отчёта -> клавиатура только под последним; двойное нажатие кнопки -> два отчёта, без ошибок; callback_data не длиннее 64 байт.

**Тесты:** `tests/unit/test_report_service.py` — periods для всех видов (граница суток в tz, неделя через смену месяца, заголовки), build_report вызывает collect_daily и format_daily с правильными периодами (fakes). `tests/unit/test_bot_report.py` — /report, каждая кнопка, ранний callback.answer, ошибка подсчёта, клавиатура только под последним сообщением.

**Контекст проекта:** Python 3.11+, aiogram 3.x. Подключение роутера, ежедневная отправка и команда в меню — шаг 088.

**Файлы:** app/reports/service.py, app/bot/keyboards.py, app/bot/handlers/report.py, tests/unit/test_report_service.py, tests/unit/test_bot_report.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.
