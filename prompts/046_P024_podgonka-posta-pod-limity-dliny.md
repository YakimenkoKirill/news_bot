## Задача

Реализуй visible_length(html) (длина видимого текста без тегов в UTF-16 code units — консервативно к подсчёту Telegram) и fit_post(post, has_photo, cfg) -> FittedPost(html, use_photo). Лимит — caption_limit при фото, иначе text_limit. Сокращается только пересказ: по концу предложения, иначе по слову с `…`. Если с фото не помещается даже минимальный пересказ min_summary_chars — use_photo=false и применяется text_limit.

**Критерий готовности:** Итоговый пост всегда укладывается в лимит, заголовок, хештеги и ссылка не обрезаются.

**Граничные случаи:** Теги и HTML-сущности никогда не разрезаются; эмодзи считается по UTF-16; пост короче лимита не меняется.

**Тесты** (`tests/unit/test_limits.py`): короткий пост, сокращение по предложению и по слову, переход на пост без фото, эмодзи, сущности &amp; на границе.

**Контекст проекта:** Python 3.11+.

**Файлы:** app/publisher/limits.py, tests/unit/test_limits.py, configs/base.yaml, app/config.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в типизированную секцию модели в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: publisher.caption_limit = 1024; publisher.text_limit = 4096; publisher.min_summary_chars = 200 (лимиты сверить с документацией Bot API).

**Формат ответа:** Полные файлы: app/publisher/limits.py, tests/unit/test_limits.py, configs/base.yaml, app/config.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
