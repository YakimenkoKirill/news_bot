## Задача

Когда другой источник пишет о том же событии, нормализация помечает новость как дубль (cluster_id указывает на первую). Этот сигнал важности сейчас теряется.

1. **Миграция 0008** (down_revision "0007"): news_items.cluster_sources (Integer, NOT NULL, default 1) — сколько **разных** источников написали об этом событии; хранится у первой (корневой) новости кластера. Заполнение для существующих данных: число различных source_id среди новостей с cluster_id = id корня плюс сам корень.
2. **Нормализация:** когда найден дубль (любого уровня) из **другого** источника, у корневой новости пересчитывается cluster_sources (`count(distinct source_id)` по кластеру) в той же транзакции. Дубль из того же источника счётчик не увеличивает.
3. **Приоритет** (`_priority` в app/db/repositories/news.py и все места, где он используется — порядок очереди, claim_next, queued_by_source, priority_of, ETA): `+ publisher.cluster_bonus × least(cluster_sources - 1, publisher.cluster_bonus_max)`. Так порядок /queue, выбор publish_due и лимит источника остаются согласованными.
4. **/queue:** у поста с cluster_sources > 1 — пометка «🔁{N}».
5. **Инвариант 8:** имена других источников в пост не выводятся.

**Критерий готовности:** Из двух новостей с одинаковой оценкой и возрастом раньше выходит та, о которой написали больше источников; бонус ограничен сверху.

**Граничные случаи:** Дубль из того же источника -> cluster_sources не меняется; цепочка дублей (дубль дубля) -> считается по корню кластера; корень уже опубликован -> счётчик обновляется, на очередь не влияет; cluster_bonus = 0 -> порядок как раньше; 10 источников при cluster_bonus_max = 3 -> бонус как за 4 источника.
