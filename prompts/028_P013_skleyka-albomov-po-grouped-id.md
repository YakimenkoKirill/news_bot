## Задача

Реализуй AlbumBuffer(wait_s, on_ready): add(message) — сообщение без grouped_id сразу передаётся в on_ready, сообщения с одним grouped_id копятся и передаются одним списком через wait_s после последнего; flush_all() отдаёт всё накопленное (при остановке). Функция merge_album(messages) выбирает текст из сообщения, где он есть, и собирает id всех фото.

**Критерий готовности:** Альбом из нескольких сообщений превращается в одну новость.

**Граничные случаи:** Новое сообщение альбома продлевает ожидание; альбомы разных каналов не смешиваются; flush_all отменяет таймеры и ничего не теряет.

**Тесты** (`tests/unit/test_telegram_albums.py`): одиночное сообщение, альбом из 3 частей, продление ожидания, два альбома параллельно, flush_all (подменённое время).

**Контекст проекта:** Python 3.11+, asyncio.

**Файлы:** app/collectors/telegram/albums.py, tests/unit/test_telegram_albums.py, configs/base.yaml, app/config.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в типизированную секцию модели в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: telegram.album_wait_s = 2.

**Формат ответа:** Полные файлы: app/collectors/telegram/albums.py, tests/unit/test_telegram_albums.py, configs/base.yaml, app/config.py. Тесты обязательны.
