# Шаг 050 из 070 · P026 · Этап 7 — Публикатор в канал

**Задача трекера:** Очередь публикаций и отправка в канал
**Результат:** app/publisher/stage_publish.py: стадия публикации
**Коммит:** `feat(publisher): стадия публикации по расписанию`

## Задача

Реализуй publish_due(now, deps) -> PublishReport: если paused — выход; next_slot по last_published_at; если слот в будущем — выход; иначе захват одного самого раннего approved/scheduled поста, check_image, build_post, fit_post, Publisher.send, запись Publication и статус published; при PublishError — Publication(failed), статус failed и алерт publish_error. Один пост за вызов.

**Критерий готовности:** За вызов публикуется не больше одного поста в разрешённый слот.

**Граничные случаи:** Неподходящая картинка -> пост без фото; пустая очередь -> отчёт без действий; два параллельных вызова не публикуют один пост дважды (claim со SKIP LOCKED).

**Тесты** (`tests/unit/test_stage_publish.py`): успешная публикация, слот в будущем, пауза, ошибка отправки, плохая картинка, пустая очередь.

**Контекст проекта:** Python 3.11+.

**Файлы:** app/publisher/stage_publish.py, tests/unit/test_stage_publish.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены.

**Формат ответа:** Полные файлы: app/publisher/stage_publish.py, tests/unit/test_stage_publish.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
