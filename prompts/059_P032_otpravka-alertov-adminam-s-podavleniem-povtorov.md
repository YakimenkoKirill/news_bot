## Задача

Реализуй AlertService(bot, admin_ids, cfg) — реализация AlertSink: форматирует AlertEvent по kind (шаблоны в texts.py), отправляет всем админам, подавляет повторы с тем же key чаще throttle_min. Ошибки отправки логируются и не пробрасываются.

**Критерий готовности:** Админы узнают о падении источников, недоступности DeepSeek, превышении бюджета и ошибках публикации.

**Граничные случаи:** Разные key не подавляют друг друга; после throttle_min повтор снова отправляется; недоступный Telegram не роняет вызывающий код.

**Тесты** (`tests/unit/test_alerts.py`): формат каждого kind, подавление, истечение паузы, ошибка отправки.

**Контекст проекта:** Python 3.11+, aiogram 3.x.

**Файлы:** app/alerts.py, app/bot/texts.py, tests/unit/test_alerts.py, configs/base.yaml, app/config.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в типизированную секцию модели в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: alerts.throttle_min = 30.

**Формат ответа:** Полные файлы: app/alerts.py, app/bot/texts.py, tests/unit/test_alerts.py, configs/base.yaml, app/config.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
