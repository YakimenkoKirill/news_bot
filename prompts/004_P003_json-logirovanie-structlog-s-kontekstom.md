## Задача

Реализуй app/logging.py: setup_logging(level: str, json_output: bool) настраивает structlog и stdlib logging (вывод в stdout, одна JSON-строка на событие, timestamp ISO-8601 UTC, level, event, logger); bind_context(**fields) — контекстный менеджер на contextvars для source_id, news_id, job; процессор mask_secrets заменяет на `***` значения SecretStr и значения ключей, совпадающих с token|key|secret|hash|password (без учёта регистра), в том числе во вложенных dict.

**Критерий готовности:** Каждая строка лога — валидный JSON с обязательными полями; поля из bind_context попадают в лог внутри блока и исчезают после выхода.

**Граничные случаи:** Секрет во вложенном dict маскируется; несериализуемый объект выводится через repr, а не роняет логгер; повторный вызов setup_logging не дублирует обработчики.

**Тесты** (`tests/unit/test_logging.py`): формат JSON и поля, контекст внутри и вне блока, маскировка SecretStr и ключей, вложенные dict, несериализуемый объект, повторная настройка.

**Контекст проекта:** Python 3.11+, structlog, logging.

**Файлы:** app/logging.py, tests/unit/test_logging.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены.

**Формат ответа:** Полные файлы: app/logging.py, tests/unit/test_logging.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
