## Задача

Реализуй app/bot/handlers/keywords.py: /keywords — два списка (include, exclude) с кнопками удаления; кнопка «Добавить» -> выбор типа -> ввод слов через запятую (FSM). Слова нормализуются как в KeywordRepository, дубли игнорируются, в ответе — что добавлено и что пропущено.

**Критерий готовности:** Админ ведёт списки слов, которые сразу применяются фильтрами.

**Граничные случаи:** Пустой ввод -> повтор вопроса; слово длиннее max_keyword_chars -> отказ для этого слова; удаление уже удалённого слова -> сообщение.

**Тесты** (`tests/unit/test_bot_keywords.py`): показ списков, добавление с дублями, пустой ввод, длинное слово, удаление.

**Контекст проекта:** Python 3.11+, aiogram 3.x.

**Файлы:** app/bot/handlers/keywords.py, app/bot/states.py, tests/unit/test_bot_keywords.py, configs/base.yaml, app/config.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в типизированную секцию модели в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: bot.max_keyword_chars = 50.

**Формат ответа:** Полные файлы: app/bot/handlers/keywords.py, app/bot/states.py, tests/unit/test_bot_keywords.py, configs/base.yaml, app/config.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
