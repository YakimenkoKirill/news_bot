# Шаг 072 из 077 · P042 · Этап 11 — Очередь публикации в боте управления

**Задача трекера:** Очередь подготовленных постов: приоритет по интересу и публикация вне очереди
**Результат:** publish_due публикует пост с наибольшим приоритетом (оценка интереса с поправкой на свежесть), а не самый старый
**Коммит:** `feat(publisher): очередь публикации по оценке интереса`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/072_P042_prioritet-publikatsii-po-otsenke-interesa.md». После коммита: `python prompts/next_step.py --done`.

## Задача

Сейчас publish_due берёт `claim_batch(PUBLISHABLE_STATUSES, 1)`, то есть самый старый одобренный пост. Сделай так, чтобы в каждый слот выходил самый интересный пост из очереди.

1. **Конфигурация:** новый ключ publisher.score_decay_per_h = 0.02 — на сколько снижается приоритет поста за каждый час возраста (0 — только по оценке). Добавь его в configs/base.yaml с комментарием и в PublisherConfig (app/config.py, `float = Field(ge=0)`). При 0,02 новость двенадцатичасовой давности теряет 0,24 оценки, поэтому свежая новость с оценкой 0,6 выйдет раньше вчерашней с 0,8.
2. **PublishNewsRepo** (app/publisher/stage_publish.py): замени в Protocol метод claim_batch на `claim_next(statuses, decay_per_h) -> QueuedNews | None` (шаг 071).
3. **publish_due:** вместо claim_batch вызывает `claim_next(PUBLISHABLE_STATUSES, deps.cfg.score_decay_per_h)`. None -> skipped="empty". Остальное поведение — пауза, слот, тихие часы, публикация, ошибки — не меняется. Обнови docstring: «захватывается пост с наибольшим приоритетом».
4. **Фильтр по оценке остаётся прежним:** посты ниже ai.min_score отсеиваются ещё на стадии ИИ. Приоритет только упорядочивает то, что уже прошло отбор.

**Критерий готовности:** При нескольких одобренных постах в слот выходит пост с наибольшим приоритетом; при score_decay_per_h = 0 — с наибольшей оценкой; остальные тесты публикации проходят.

**Граничные случаи:** Один пост в очереди -> публикуется он; равные приоритеты -> меньший id; посты в scheduled участвуют наравне с approved; score_decay_per_h отрицательный в yaml -> ошибка конфигурации при запуске; ключа нет в yaml -> ошибка при запуске (extra="forbid" и обязательное поле, как у остальных ключей).

**Тесты:** `tests/unit/test_stage_publish.py` — замени в fake NewsRepo метод claim_batch на claim_next, который сортирует по той же формуле (оценку бери из fake-постов, возраст — из published_at или created_at fake-новости); тест, который проверял «самый старый первым» (`News(2, created_at=NOON - timedelta(hours=2))`), перепиши на проверку приоритета: при decay = 0 выходит пост с большей оценкой, при decay > 0 свежий пост обгоняет старый с чуть большей оценкой. Остальные проверки этого файла не ослабляй. `tests/unit/test_config.py` (или файл, где проверяется секция publisher) — ключ читается, отрицательное значение отклоняется. Если `tests/integration/test_pipeline.py` опирается на порядок публикации, приведи его ожидания к новому правилу, не убирая проверок.

**Контекст проекта:** Python 3.11+. Порядок вкладки «В очереди» в /queue (шаг 075) считается той же формулой, поэтому номер поста в списке совпадает с порядком выхода.

**Файлы:** app/publisher/stage_publish.py, configs/base.yaml, app/config.py, tests/unit/test_stage_publish.py, тест конфигурации секции publisher; при необходимости tests/integration/test_pipeline.py.
