## Задача

Напиши scripts/run_report.py --from --to: считает по БД число публикаций, медиану и p95 задержки (publications.published_at - news_items.published_at), долю отклонённых модератором, число пойманных дублей по уровням, расход DeepSeek по дням, ошибки источников, и сравнивает с целями MVP из секции metrics (печатает таблицу ok/fail). Логика — в функциях для тестов.

**Критерий готовности:** Отчёт за период печатается и показывает выполнение каждой метрики MVP.

**Граничные случаи:** Период без данных -> нули и пометка «нет данных»; новости без published_at не входят в задержку; даты периода в часовом поясе app.timezone.

**Тесты** (`tests/integration/test_run_report.py`): расчёт каждой метрики на подготовленных строках, пустой период, сравнение с целями.

**Контекст проекта:** Python 3.11+, SQLAlchemy 2.0 async, argparse.

**Файлы:** scripts/run_report.py, tests/integration/test_run_report.py, configs/base.yaml, app/config.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в типизированную секцию модели в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: metrics.max_delay_min = 15; metrics.max_rejected_share = 0.2; metrics.max_duplicate_share = 0.02.

**Формат ответа:** Полные файлы: scripts/run_report.py, tests/integration/test_run_report.py, configs/base.yaml, app/config.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/). Команды проверки: make db-up && make test-integration.
