# Шаг 081 из 082 · P047 · Этап 12 — Журнал ошибок в боте управления

**Задача трекера:** Просмотр ошибок в боте управления
**Результат:** Команда /errors: открытые и все инциденты, карточка ошибки, «Решено», заглушить вид, упавшие новости с кнопкой «Повторить»
**Коммит:** `feat(bot): команда /errors — журнал ошибок`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/081_P047_komanda-errors-v-bote.md». После коммита: `python prompts/next_step.py --done`.

## Задача

1. **Клавиатуры** (app/bot/keyboards.py):
   - `ErrorTab(StrEnum)`: `open` — открытые инциденты, `all` — все инциденты, `news` — новости в failed.
   - `ErrorActionType(StrEnum)`: `page`, `open`, `back`, `resolve`, `resolve_all`, `confirm_all`, `mute`, `retry`.
   - `ErrorAction(CallbackData, prefix="er")`: action, tab, page, id (по умолчанию 0) — id инцидента или новости.
   - `errors_keyboard(ids_with_numbers, tab, page, has_prev, has_next, can_resolve_all)` — «🔎 N» на каждую запись, строка вкладок («Открытые» / «Все» / «Новости»; активная помечена «•»), навигация ◀️ ▶️, на вкладке open при наличии записей — «✅ Решить все».
   - `incident_keyboard(incident_id, kind_muted: bool, is_open: bool, tab, page)` — «✅ Решено» (только для открытого), «🔕 Не присылать в чат» / «🔔 Присылать в чат», «◀️ К списку».
   - `failed_news_keyboard(news_id, tab, page)` — «🔁 Повторить», «◀️ К списку».
   - `confirm_resolve_all_keyboard(tab, page)` — «Да, закрыть все» (confirm_all) и «Отмена» (back).
2. **Тексты** (app/bot/texts.py):
   - `ALERT_KIND_LABELS` — человекочитаемое имя каждого AlertKind (тест: ключи совпадают со всеми AlertKind).
   - Строка списка: «{N}. {эмодзи из шаблона} {название вида} ×{count} · {последний раз ЧЧ:ММ или ДД.ММ ЧЧ:ММ} — {начало сообщения}»; начало обрезай truncate_words до bot.error_preview_chars, всё экранируй.
   - Карточка: вид, key, «Первый раз / последний раз» в app.timezone, «Повторов: N», статус («открыта» или «решена {кем} {когда}»), пометка «🔕 не присылается в чат», если вид заглушён, полный текст сообщения (обрезанный под publisher.text_limit).
   - Строка новости: «{N}. {заголовок} — {источник} · {причина}»; карточка: заголовок, источник, ссылка, причина (`bad_ai_response` -> «модель вернула некорректный ответ», `publish_error` -> «не удалось опубликовать», `no_processed_post` -> «нет пересказа», иначе как есть), что сделает «Повторить» (снова в модель или снова в очередь публикации).
   - Пустые вкладки, «Уже решено», итоги повтора («Новость снова отправлена в модель», «Новость снова в очереди публикации», «Новость уже не в статусе failed: {статус}», «Новость не найдена»).
3. **Обработчик** app/bot/handlers/errors.py:
   - `@dataclass(frozen=True) ErrorsDeps`: session_scope, incident_repo, news_repo, source_repo, settings_repo (Protocol с нужными методами), retry (RetryDeps из шага 080), silent_kinds (frozenset[AlertKind] из alerts.silent_kinds), page_size (bot.page_size), preview_chars (bot.error_preview_chars), text_limit (publisher.text_limit), tz, clock.
   - Заглушённые виды хранятся в настройке `MUTED_KINDS_SETTING = "alerts_muted"` (список строк) через SettingsRepository. Вид считается заглушённым, если он в этой настройке или в silent_kinds. Кнопка «🔕/🔔» меняет только настройку; для вида из silent_kinds кнопка «🔔» отвечает alert «Вид отключён в configs (alerts.silent_kinds)» и ничего не меняет.
   - `/errors` -> вкладка open, страница 0. Заголовок: «<b>Ошибки</b> · открыто N» и строка по видам из count_open_by_kind, например «источники 2 · публикация 1».
   - `page` -> редактирует список; `open` -> карточка новым сообщением (для вкладки news — карточка новости); `back` -> список.
   - `resolve` -> `resolve(id, by=user_id, at=clock())`; True -> карточка обновляется (статус «решена», кнопки без «Решено»), False -> alert «Уже решено».
   - `resolve_all` -> клавиатура подтверждения; `confirm_all` -> `resolve_all(by, at)` и ответ «Закрыто: N», список обновляется.
   - `mute` -> переключение вида в настройке, карточка обновляется.
   - `retry` -> `retry_failed` и текст итога; кнопка «Повторить» убирается.
   - Номер страницы зажимается в допустимый диапазон, как в sources.render_page.
   - `create_router()` регистрирует /errors и `ErrorAction.filter()`.
4. **Конфигурация:** bot.error_preview_chars = 80 — в configs/base.yaml и в BotConfig (Field(ge=1)).

**Критерий готовности:** Админ в любой момент открывает /errors и видит, что сломалось, сколько раз и когда; закрывает решённое; отключает в чате шумные виды, не теряя их в журнале; повторяет упавшие новости одной кнопкой.

**Граничные случаи:** Пустой журнал -> «Ошибок нет ✅» и строка вкладок; инцидент закрыт другим админом между показом и нажатием -> «Уже решено»; «Решить все» при пустой вкладке не показывается; вкладка all показывает и закрытые с пометкой ✅; сообщение с HTML-символами экранировано; очень длинный message не превышает лимит сообщения Telegram; callback_data каждой кнопки не длиннее 64 байт при больших id; повтор новости, которую уже повторил другой админ, -> «уже не в статусе failed».

**Тесты** (`tests/unit/test_bot_errors.py`): каждая вкладка и пагинация, заголовок со счётчиками по видам, карточка открытого и закрытого инцидента, resolve и повторный resolve, resolve_all с подтверждением и отменой, mute/unmute и вид из silent_kinds, retry для каждого исхода, экранирование, длина callback_data, совпадение ALERT_KIND_LABELS с AlertKind. Fakes — по образцу tests/unit/test_bot_sources.py.

**Контекст проекта:** Python 3.11+, aiogram 3.x. Подключение роутера, команды в меню и чтение заглушённых видов в AlertService — шаг 082.

**Файлы:** app/bot/keyboards.py, app/bot/texts.py, app/bot/handlers/errors.py, configs/base.yaml, app/config.py, tests/unit/test_bot_errors.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Смена статуса новости — только через retry_failed (шаг 080). Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в типизированную секцию модели в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: bot.error_preview_chars = 80. texts.COMMANDS в этом шаге не меняй (это шаг 082).

**Формат ответа:** Полные файлы: app/bot/keyboards.py, app/bot/texts.py, app/bot/handlers/errors.py, configs/base.yaml, app/config.py, tests/unit/test_bot_errors.py. Тесты обязательны.
