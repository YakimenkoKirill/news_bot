## Задача

Реализуй process_new_batch(now, deps) -> StageReport: в одной транзакции claim_batch(new, batch_size), для каждой новости normalize_item -> update_fields -> apply_filters (слова из KeywordRepository) -> Deduplicator, затем set_status в filtered, duplicate или normalized с reject_reason и cluster_id. Каждая новость — в bind_context(news_id=...).

**Критерий готовности:** Все захваченные новости получают итоговый статус и причину.

**Граничные случаи:** Ошибка разбора одной новости переводит её в filtered с reason=normalize_error и не роняет пачку; пустая очередь -> отчёт с нулями.

**Тесты** (`tests/unit/test_stage_normalize.py`): все три исхода, ошибка одной новости, пустая очередь, отчёт (фейковые репозитории).

**Контекст проекта:** Python 3.11+.

**Файлы:** app/pipeline/stage_normalize.py, tests/unit/test_stage_normalize.py, configs/base.yaml, app/config.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в типизированную секцию модели в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: pipeline.batch_size = 20.

**Формат ответа:** Полные файлы: app/pipeline/stage_normalize.py, tests/unit/test_stage_normalize.py, configs/base.yaml, app/config.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
