# Шаг 076 из 077 · P043 · Этап 11 — Очередь публикации в боте управления

**Задача трекера:** Очередь подготовленных постов в боте управления
**Результат:** Кнопка «🚀 Опубликовать сейчас» с подтверждением под предпросмотром поста из /queue
**Коммит:** `feat(bot): публикация поста вне очереди из бота`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/076_P043_knopka-opublikovat-vne-ocheredi.md». После коммита: `python prompts/next_step.py --done`.

## Задача

1. **Клавиатуры** (app/bot/keyboards.py): добавь в QueueActionType действия `publish`, `confirm`, `cancel`. В queue_item_keyboard первой строкой — «🚀 Опубликовать сейчас» (publish), второй — «◀️ К списку». Новая `queue_confirm_keyboard(news_id, tab, page)`: «✅ Да, опубликовать» (confirm) и «Отмена» (cancel).
2. **Тексты** (app/bot/texts.py): подсказка подтверждения «Опубликовать сейчас, вне очереди? Интервал между постами и тихие часы не учитываются.» (на паузе дописывается «Пайплайн на паузе — пост всё равно выйдет.»); «Публикую…»; итоги: «🚀 Опубликовано вне очереди», «Пост сейчас публикуется — обновите список», «Уже обработано: {статус}», «Пост не найден», «❌ Не удалось опубликовать: {ошибка}».
3. **Обработчик** (app/bot/handlers/queue.py): добавь в QueueDeps поле `manual: ManualPublishDeps` (шаг 073) и обработай:
   - `publish` -> меняет только клавиатуру сообщения с предпросмотром на queue_confirm_keyboard (edit_reply_markup) и отвечает callback.answer с подсказкой подтверждения.
   - `cancel` -> возвращает queue_item_keyboard.
   - `confirm` -> сразу `callback.answer(«Публикую…»)`: у Telegram ограничено время на ответ, а публикация с проверкой картинки и повторами может идти дольше. Затем `publish_now(news_id, clock(), deps.manual, initiator_id=from_user.id)` и разбор итога:
     - published -> `mark_message` (шаг 074): кнопки убираются, дописывается «🚀 Опубликовано вне очереди — @who»;
     - busy -> сообщение «сейчас публикуется», кнопки остаются;
     - already_done -> `mark_message` с «Уже обработано: {статус}»;
     - not_found -> `mark_message` с «Пост не найден»;
     - failed -> `mark_message` с «❌ Не удалось опубликовать: {ошибка}» (статус failed, алерт publish_error всем админам уже отправил publish_item).
   - Лог `queue.publish_now` с news_id, user_id и outcome.
   - Расширь фильтр роутера на publish, confirm и cancel.
4. Сообщения модерации для поста из вкладки review, уже разосланные другим админам, менять не нужно: их кнопки и так ответят «Уже обработано: published» (StaleStatusError в handlers/moderation.py).

**Критерий готовности:** Админ открывает пост в /queue, нажимает «Опубликовать сейчас», подтверждает, и пост сразу выходит в канал; в чате видно, кто и когда это сделал; двойное нажатие или два админа не публикуют пост дважды.

**Граничные случаи:** Двойное нажатие «Да» -> второй вызов получает already_done; пост в эту секунду публикует publish_due -> busy; пост с вкладки review (pending_review) -> публикуется (через approved); пауза -> публикуется, в подсказке предупреждение; ошибка Telegram при публикации -> failed с текстом ошибки, без исключения в обработчике; «Отмена» возвращает исходные кнопки; callback_data новых кнопок не длиннее 64 байт.

**Тесты** (`tests/unit/test_bot_queue_publish.py`): publish -> клавиатура подтверждения; cancel; confirm для каждого исхода (published, busy, already_done, not_found, failed) с проверкой текста и кнопок; callback.answer вызван до publish_now (порядок вызовов в fake); предупреждение о паузе; длина callback_data. publish_now в тестах — fake с заданным исходом.
