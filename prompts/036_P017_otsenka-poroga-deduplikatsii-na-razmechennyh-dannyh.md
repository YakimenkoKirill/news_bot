## Задача

Напиши scripts/eval_dedup.py: читает JSONL с полями id, title, text, cluster (размеченные человеком дубли), для порогов 0..10 считает долю пропущенных дублей и долю ложных склеек и печатает таблицу; рекомендует минимальный порог, при котором пропуск <= 2% (цель MVP). Логику вынеси в функцию evaluate(records, thresholds) для тестов.

**Критерий готовности:** Скрипт печатает таблицу и рекомендацию на любом размеченном файле.

**Граничные случаи:** Пустой файл -> понятная ошибка; запись без cluster -> ошибка с номером строки; если ни один порог не даёт <= 2% — так и сообщается.

**Тесты** (`tests/unit/test_eval_dedup.py`): маленькая синтетическая выборка с известным ответом, пустой файл, битая строка.

**Контекст проекта:** Python 3.11+, argparse, json.

**Файлы:** scripts/eval_dedup.py, tests/fixtures/dedup/sample.jsonl, tests/unit/test_eval_dedup.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Настоящий набор из 200 размеченных новостей собирает человек; синтетические данные в тесте — только для проверки логики.

**Формат ответа:** Полные файлы: scripts/eval_dedup.py, tests/fixtures/dedup/sample.jsonl, tests/unit/test_eval_dedup.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
