# Шаг 086 из 088 · P049 · Этап 13 — Ежедневный отчёт в боте управления

**Задача трекера:** Ежедневный отчёт: подсчёт и текст
**Результат:** format_daily — отчёт в HTML для Telegram, разбитый на сообщения по лимиту
**Коммит:** `feat(reports): текст ежедневного отчёта`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/086_P049_tekst-ezhednevnogo-otcheta.md». После коммита: `python prompts/next_step.py --done`.

## Задача

Реализуй `format_daily(report: DailyReport, title: str, cfg: DailyReportConfig, text_limit: int) -> list[str]` в app/reports/daily_format.py. Возвращает одно или несколько HTML-сообщений, каждое не длиннее text_limit (publisher.text_limit) в UTF-16 (utf16_len из app/publisher/limits.py).

Структура (блоки разделены пустой строкой, заголовки блоков жирные):

1. **Заголовок:** «📊 <b>Отчёт за {title}</b>» (title формирует вызывающий: «14 октября», «вчера», «7–13 октября»). Если пайплайн на паузе — строка «⏸ Пайплайн на паузе».
2. **Итог одной строкой:** «Опубликовано {N} {пост/поста/постов} · собрано {M} · потрачено ${X}» и рядом изменения к прошлому периоду: «▲ +3», «▼ −2», «= 0»; для расхода — в долларах.
3. **Публикации:** по расписанию / вне очереди / отредактировано модератором / неудачных; самый активный час; «Лучшие посты»: «★0.91 Заголовок — Источник» ссылкой на пост в канале.
4. **Источники:** таблица в `<pre>` моноширинным шрифтом: источник | собрано | в канал | дубли | отсеяно | ср. оценка. Не больше daily_report.top_sources строк, остальные — одной строкой «прочие (K)». Источники с error_count > 0 помечены «⚠️», выключенные — «⏸». Имена обрезаются до daily_report.source_name_chars.
5. **Воронка:** «Собрано 120 → дубли 18 → фильтры 40 → модель 62 → не по теме 30 → на модерации 2 → в очереди 5 → опубликовано 25»; ниже раскрытие фильтров по причинам и дублей по уровням одной строкой каждое.
6. **Модель:** «${X} из ${budget} ({P}%)», запросов, токены вход/выход (с разделителями тысяч), стоимость поста, расход с начала месяца. При доле бюджета ≥ daily_report.budget_warn_share — «⚠️».
7. **Качество:** медиана и p95 задержки в минутах, средняя оценка опубликованных, доля дублей в канале и доля отклонённых модератором — с отметкой ✅/❌ по целям из секции metrics (compare_with_targets); «нет данных» вместо None.
8. **Сейчас:** в очереди N (лучший: ★оценка «заголовок»), на модерации M.
9. **Ошибки:** «Открыто N · новых за день K (по видам)» и «новостей с ошибкой L»; при N > 0 — подсказка «/errors». Если ошибок нет — «Ошибок нет ✅».

Правила:
- Весь текст из БД (заголовки, имена источников) экранируется html.escape, в том числе внутри `<pre>`.
- Пустые блоки не выводятся, кроме «Итога» и «Модели» (для них нули).
- Разбиение по сообщениям — только между блоками; если один блок длиннее лимита (таблица источников), он режется по строкам, и каждый кусок `<pre>` закрывается и открывается заново.
- Склонение «пост/поста/постов» — функция `plural(n, forms)`.
- Числа без магических констант: все пороги и длины — из DailyReportConfig.

**Критерий готовности:** Отчёт читается за минуту на телефоне, все цифры из DailyReport на месте, ни одно сообщение не превышает лимит, HTML валиден для Telegram (теги сбалансированы).

**Граничные случаи:** Пустой день — короткий отчёт: итог с нулями, модель, «Ошибок нет ✅»; 50 источников — таблица обрезана до top_sources + «прочие»; имя источника с `<` и `&`; длинный блок разбит на несколько сообщений с корректными `<pre>`; склонение для 1, 2, 5, 11, 21, 111; отрицательные и нулевые изменения к прошлому периоду.

**Тесты** (`tests/unit/test_daily_format.py`): каждый блок на фикстуре DailyReport, пустой день, обрезка источников, экранирование, разбиение по лимиту (маленький text_limit в тесте) с проверкой баланса тегов, plural, стрелки изменений, предупреждение о бюджете, отметки целей.

**Контекст проекта:** Python 3.11+. Форматирование не зависит от aiogram и БД — только от DailyReport.

**Файлы:** app/reports/daily_format.py, tests/unit/test_daily_format.py, configs/base.yaml, app/config.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в DailyReportConfig в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: daily_report.top_sources = 10, daily_report.source_name_chars = 18, daily_report.budget_warn_share = 0.8.

**Формат ответа:** Полные файлы: app/reports/daily_format.py, tests/unit/test_daily_format.py, configs/base.yaml, app/config.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий] и пример отчёта на фикстуре из тестов. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
