## Задача

Реализуй app/health.py с async check(settings) -> HealthResult(ok, reasons): БД отвечает на SELECT 1 за db_timeout_s и heartbeat_at из настроек моложе max_age_s. Запуск `python -m app.health` печатает результат и завершается с кодом 0 или 1.

**Критерий готовности:** Healthcheck контейнера отражает реальную работоспособность планировщика и БД.

**Граничные случаи:** Нет heartbeat_at (первый старт) -> ok в течение startup_grace_s после старта процесса (время старта пишется вместе с heartbeat); недоступная БД -> код 1 без трейсбека.

**Тесты** (`tests/unit/test_health.py`): здоровое состояние, старый heartbeat, нет heartbeat, недоступная БД, коды выхода.

**Контекст проекта:** Python 3.11+, SQLAlchemy 2.0 async.

**Файлы:** app/health.py, tests/unit/test_health.py, configs/base.yaml, app/config.py.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). .gitignore не менять. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Новые ключи конфигурации добавь в configs/base.yaml и в типизированную секцию модели в app/config.py; ключи, помеченные «задаёт человек», не заполняй сам — если их нет в configs/base.yaml, перечисли пробел и остановись. Ключи этого шага: health.max_age_s = 180; health.db_timeout_s = 5; health.startup_grace_s = 300.

**Формат ответа:** Полные файлы: app/health.py, tests/unit/test_health.py, configs/base.yaml, app/config.py. Тесты обязательны. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
