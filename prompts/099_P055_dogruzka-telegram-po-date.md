## Задача

TelegramCollector._catch_up_channel (app/collectors/telegram/collector.py) берёт до telegram.catch_up_limit сообщений по min_id без ограничения по дате. На новом канале это 100 сообщений за много дней: они сохраняются в БД и только потом отсеиваются фильтром too_old (в прошлом прогоне — 142 из 175).

1. Граница: `cutoff = now - filters.max_age_h`. Сообщения приходят от новых к старым (iter_messages по умолчанию) — прекращай итерацию на первом сообщении с `date < cutoff`. Ограничение catch_up_limit сохраняется.
2. Сообщения старше cutoff внутри альбома: альбом склеивается как раньше, решение по дате — по самому новому сообщению альбома.
3. Лог `telegram.caught_up` дополни полем `stopped_by_age` (True/False).
4. TelegramCollector получает cutoff-часы через конструктор (FiltersConfig.max_age_h или отдельное значение) — не читай конфигурацию глобально. Часы — через инжектируемый clock для тестов.
5. Новые сообщения в реальном времени (NewMessage) не меняются.

**Критерий готовности:** При подключении нового канала в БД попадают только сообщения за последние max_age_h часов; число отсеянных too_old при догрузке близко к нулю.

**Граничные случаи:** Канал без новых сообщений -> ничего не грузится; все 100 последних сообщений свежие -> работает как раньше (limit); первое же сообщение старое -> ни одного; сообщение без даты -> считается свежим (как было), лог warning; альбом на границе cutoff.

**Тесты:** `tests/unit/test_telegram_collector.py` — fake iter_messages с сообщениями разных дат: остановка по дате, по limit, альбом на границе, сообщение без даты, флаг в логе.

**Контекст проекта:** Python 3.11+, Telethon. Фильтр too_old в нормализации остаётся — это вторая линия защиты.
