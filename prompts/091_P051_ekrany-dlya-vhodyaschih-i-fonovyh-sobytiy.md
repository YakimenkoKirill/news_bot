# Шаг 091 из 096 · P051 · Этап 14 — Один экран в чате бота

**Задача трекера:** Один экран: хранение и учёт сообщений
**Результат:** Каждое действие админа и каждое фоновое событие открывает свой экран; сообщения админа удаляются после обработки
**Коммит:** `feat(bot): экраны для действий админа и фоновых событий`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/091_P051_ekrany-dlya-vhodyaschih-i-fonovyh-sobytiy.md». После коммита: `python prompts/next_step.py --done`.

## Задача

1. **`ScreenUpdateMiddleware(cfg)`** в app/bot/screen.py — внешний middleware диспетчера для message и callback_query:
   - оборачивает вызов handler в `new_screen()`, чтобы всё, что бот отправит в ответ на эту команду или кнопку, стало одним экраном и заменило прошлый;
   - для message, если `cfg.single_screen` и `cfg.delete_user_messages` включены и чат личный (chat.type == "private"), после handler (в finally, то есть и при исключении) удаляет само сообщение админа `message.delete()`. Ошибки удаления (TelegramBadRequest) логируются на уровне info и не пробрасываются;
   - сообщение админа удаляется и тогда, когда handler ничего не отправил (например, ввод в диалоге, который только редактирует прошлое сообщение);
   - callback_query сообщения не удаляет — редактирование сообщения под кнопкой (edit_text, edit_reply_markup) экран не меняет.
2. **Порядок middleware** в create_dispatcher (app/bot/__init__.py): AdminOnlyMiddleware первым, ScreenUpdateMiddleware после него — посторонним экран не создаётся, а их сообщения не удаляются. BotDeps получает новое необязательное поле `screen_middleware: ScreenUpdateMiddleware | None = None`; create_dispatcher ставит его на message и callback_query только если оно передано. Не включай middleware автоматически по deps.settings.ui: Settings в тестах уже содержит секцию ui (шаг 090), и существующие тесты диспетчера начали бы удалять fake-сообщения.
3. **Фоновые отправки** — каждая открывает свой экран через `with new_screen():`
   - AlertService.emit (app/alerts.py) — отдельный экран на каждого админа: оборачивай отправку внутри цикла по админам;
   - BotReviewNotifier.notify (app/bot/moderation.py) — заметка «Проверьте перед публикацией» и сам черновик — один экран для одного админа;
   - DailyReportSender.send_due (app/reports/sender.py) — все части отчёта одному админу — один экран.
   Другие места не меняй: всё, что отправляется в ответ на апдейт, уже внутри экрана из ScreenUpdateMiddleware.

**Критерий готовности:** Команда, нажатие кнопки, алерт, черновик на модерацию и ежедневный отчёт заменяют прошлый экран; многочастный отчёт и «заметка + черновик» остаются вместе; сообщения админа исчезают после обработки.

**Граничные случаи:** handler бросил исключение -> сообщение админа всё равно удалено, исключение проброшено дальше как раньше; сообщение админа в группе (не private) не удаляется; delete_user_messages = false -> сообщения админа остаются, экраны бота всё равно сменяются; single_screen = false -> middleware ничего не делает; алерт двум админам -> у каждого свой экран; посторонний пользователь -> отказ как раньше, его сообщение не удаляется.

**Тесты:** `tests/unit/test_bot_screen.py` — дописать ScreenUpdateMiddleware: новый токен внутри handler, удаление сообщения после handler и при исключении, callback без удаления, флаги, не-private чат. `tests/unit/test_alerts.py`, `tests/unit/test_bot_review_notify.py`, `tests/unit/test_report_sender.py` — дописать проверку, что отправка идёт внутри нового экрана (current_screen() в fake-боте отличается между событиями и совпадает внутри одного). `tests/unit/test_bot_middleware.py` — порядок middleware. Старые проверки не ослабляй.
