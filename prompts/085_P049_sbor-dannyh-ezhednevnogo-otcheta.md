## Задача

Реализуй `collect_daily(session, period: Period, previous: Period, ctx: DailyContext) -> DailyReport` в app/reports/daily.py. `DailyContext` (frozen dataclass): tz, daily_budget, decay_per_h (publisher.score_decay_per_h), top_posts (daily_report.top_posts). Все результаты — frozen dataclass'ы.

1. **Публикации** (по Publication.published_at в периоде, status = sent):
   - всего постов; из них по расписанию (initiated_by IS NULL) и вне очереди (initiated_by NOT NULL);
   - отредактированных модератором (processed_posts.edited_by NOT NULL);
   - неудачных публикаций (status = failed);
   - по часам: словарь час (0–23 в tz) -> количество;
   - топ-N постов дня по relevance_score: заголовок, источник, оценка, message_id и ссылка `https://t.me/c/{channel_id без префикса -100}/{message_id}`.
2. **По источникам** — для каждого источника, у которого в периоде было хоть что-то: собрано новостей (news_items.created_at в периоде), опубликовано (по публикациям периода), дублей, отсеяно фильтрами, отклонено моделью (not_relevant), отклонено модератором, ошибок модели (failed по bad_ai_response), средняя оценка интереса пересказов, расход на модель; плюс текущий error_count источника и признак enabled. Сортировка: по опубликованным, затем по собранным.
3. **Воронка новостей, собранных за период** (по created_at, текущий статус): собрано -> дубли (по уровням из reject_reason duplicate:…) -> отсеяно фильтрами (по причинам: too_old, language, stop_word, no_keyword — префикс reject_reason до «:») -> обработано моделью -> не по теме -> ошибки модели -> на модерации -> отклонено модератором -> в очереди -> опубликовано. Новости, собранные вчера и опубликованные сегодня, в воронку не входят, но входят в «Публикации» — отметь это в docstring.
4. **Расход на модель:** сумма cost, запросов (число processed_posts), токены вход/выход за период; доля дневного бюджета; стоимость одного опубликованного поста (расход / публикации, None при 0); расход с начала месяца (в tz).
5. **Качество:** медиана и p95 задержки «вышло в источнике -> вышло в канале» и доля дублей в канале — через `collect_report` из app/reports/metrics.py (шаг 083), без копирования логики; средняя оценка опубликованных постов; доля отклонённых модератором.
6. **Состояние на момент отчёта:** в очереди (approved + scheduled), на модерации, лучший пост очереди по приоритету (list_prepared из шага 071, limit 1) — заголовок и оценка; пауза (настройка paused).
7. **Ошибки:** открытых инцидентов; новых инцидентов за период по видам (first_seen_at в периоде); новостей, перешедших в failed за период (созданных в периоде и находящихся в failed).
8. **Сравнение с предыдущим периодом:** для публикаций, собранных новостей и расхода — значение за previous (тем же кодом, без повторного полного отчёта: отдельная лёгкая функция `_headline(session, period)`).

Каждую группу считай отдельной приватной функцией с агрегирующими SQL-запросами (GROUP BY в БД, а не перебор строк в Python), чтобы отчёт за месяц не тянул все строки в память.

**Критерий готовности:** На размеченных данных все числа отчёта совпадают с ожидаемыми; пустой день даёт нули и None, а не исключения.

**Граничные случаи:** День без публикаций -> стоимость поста None; удалённый источник (новости остались, источника нет) — строка «удалённый источник #id»; новость опубликована сегодня, а собрана вчера -> в публикациях есть, в воронке нет; полночь в tz, а не в UTC (новость в 23:30 МСК — это сегодня, хотя в UTC уже другая дата); расход с начала месяца в первый день месяца = расходу за день; несколько неудачных публикаций одной новости считаются каждая.

**Тесты** (`tests/integration/test_daily_report.py`, маркер integration): один наполненный день с двумя источниками и всеми статусами — проверка каждой группы; пустой день; граница суток по Москве; сравнение с предыдущим днём; удалённый источник; публикации вне очереди и отредактированные.
