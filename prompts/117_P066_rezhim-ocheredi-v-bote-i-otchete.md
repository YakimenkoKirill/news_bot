# Шаг 117 из 117 · P066 · Этап 21 — Порядок очереди без учёта источника

**Задача трекера:** Порядок очереди без учёта источника
**Результат:** Режим порядка очереди виден и переключается в боте: /settings, /queue, /status; README
**Коммит:** `feat(bot): режим порядка очереди в /settings, /queue и /status`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/117_P066_rezhim-ocheredi-v-bote-i-otchete.md». После коммита: `python prompts/next_step.py --done`.

## Задача

1. **/settings** (app/bot/texts.py, handlers/settings.py): код `source` -> `publisher.source_aware` в SETTINGS_CODES; название «Учитывать источник»; пресеты `(("true", "Вкл — бонус и лимит источника"), ("false", "Выкл — только интерес и свежесть"))` в SETTINGS_PRESETS — существующий механизм пресетов уже отправляет значение в RuntimeConfig.set; format_value показывает bool как «вкл»/«выкл».
2. **/queue** (handlers/queue.py, texts.py): под заголовком вкладки «В очереди» строка режима: при source_aware = false — «Порядок: интерес и свежесть, источник не учитывается»; при true — «Порядок: интерес, свежесть и число источников; лимит источника {max}». При false не показываются заполненность «N/max» и «🔒» и пометка «🔁{N}» (они относятся к источнику).
3. **/status:** строка «Порядок очереди: …» тем же текстом; строка о заполненных источниках — только при true (это уже обеспечивает effective_max_queued из шага 116 — проверь).
4. **Ежедневный отчёт:** строки «вытеснено лимитом источника» выводятся только если за период были такие новости — уже так; при false в блоке «Сейчас» добавь «очередь без учёта источника», чтобы было видно, в каком режиме работает канал. DailyContext (app/reports/daily.py) получает поле `source_aware: bool = True`; в app/reports/service.py при сборке контекста бери значение из снимка RuntimeConfig, если он передан в ReportDeps (добавь необязательное поле `runtime`), иначе из settings.publisher; в app/main.py передай runtime. В docstring укажи, что это режим на момент отчёта, а не за все сутки.
5. **README.md:** раздел «Порядок очереди»: формула приоритета; что такое режим «Учитывать источник» и что он включает (бонус за число источников, лимит источника); как переключить (/settings или PUBLISHER__SOURCE_AWARE); что при включении лишние посты сразу вытесняются, а при выключении ничего не возвращается.

**Критерий готовности:** Админ видит текущий режим в /queue и /status и переключает его в /settings одной кнопкой; изменение действует без перезапуска.

**Граничные случаи:** Переключение в /settings -> /queue сразу показывает новый порядок (не позже runtime.cache_s); при false в /queue нет 🔒, N/max и 🔁; при true — есть; «↩️ Как в конфиге» возвращает значение из yaml; длина callback_data пресетов ≤ 64 байт.

**Тесты:** `tests/unit/test_bot_settings.py` — пресеты source и отображение «вкл/выкл»; `tests/unit/test_bot_queue.py` — строка режима и скрытие пометок при false, прежний вид при true; `tests/unit/test_bot_status.py` — строка порядка в обоих режимах; `tests/unit/test_daily_format.py` — пометка режима в блоке «Сейчас»; `tests/unit/test_report_service.py` — source_aware берётся из runtime, а без него из settings; `tests/unit/test_readme.py` проходит.
