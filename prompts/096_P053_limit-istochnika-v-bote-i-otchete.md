# Шаг 096 из 096 · P053 · Этап 15 — Лимит источника в очереди публикации

**Задача трекера:** Лимит источника: подключение
**Результат:** Очистка очереди при старте, заполненность по источникам в /queue и /status, вытесненные в ежедневном отчёте, README
**Коммит:** `feat(app): лимит источника в очереди — старт, бот и отчёт`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/096_P053_limit-istochnika-v-bote-i-otchete.md». После коммита: `python prompts/next_step.py --done`.

## Задача

1. **Очистка при старте** (app/main.py): компонент `QueueTrimComponent` запускается после DatabaseComponent и до планировщика. В start одной транзакцией вызывает `trim_queue` (шаг 094) с настройками publisher и пишет лог `queue_limit.trimmed` с числом вытесненных. Так очередь, накопленная до включения лимита или до уменьшения max_queued_per_source, приводится к лимиту. Ошибка — `log.exception` и исключение пробрасывается (как у других компонентов: приложение не стартует с неизвестным состоянием очереди). stop ничего не делает.
2. **/queue** (app/bot/handlers/queue.py, app/bot/texts.py): render_page получает `queue_counts_by_source` (шаг 093) одним запросом на страницу. В строке вкладки «В очереди» после источника — заполненность «{N}/{max}», при N = max — «🔒{N}/{max}». При max = 0 заполненность не показывается. Вкладка «На модерации» не меняется.
3. **/status** (app/bot/handlers/status.py): строка «Очередь заполнена у источников: Bell 4/4, Хабр 4/4», если такие есть; иначе строки нет. При max = 0 строки нет. StatusDeps получает max_queued_per_source.
4. **Ежедневный отчёт** (app/reports/daily.py и app/reports/daily_format.py):
   - в Funnel и SourceStats новое поле `queue_limited` — новости в filtered с причиной REASON_QUEUE_LIMIT (импорт из app/pipeline/queue_limit.py, как REASON_NOT_RELEVANT импортируется из processor.py); из `filtered` и `filtered_by_reason` они исключаются, чтобы не смешиваться с фильтрами возраста, языка и слов;
   - в воронке после «модель» — «→ вытеснено лимитом источника {N}», только если N > 0;
   - в таблице источников колонка не добавляется (ширина важна на телефоне); вместо этого под таблицей строка «Вытеснено лимитом: Bell 3, Хабр 1», если есть.
5. **README.md:** раздел «Лимит источника в очереди»: правило (не больше publisher.max_queued_per_source постов одного источника в очереди; остаются самые сильные по приоритету); что происходит с лишними (filtered с причиной queue_limit, в канал не попадают); решения админа (одобрение, правка, «Повторить») встают в очередь всегда, вытесняя слабейший автоматический пост; «Опубликовать сейчас» лимит не проверяет; как отключить (`PUBLISHER__MAX_QUEUED_PER_SOURCE=0`); что при старте лишнее вытесняется; где это видно (/queue, /status, отчёт); вытесненная новость уже прошла через модель — это расход.

**Критерий готовности:** После перезапуска очередь соответствует лимиту; админ видит заполненность в /queue и /status; отчёт показывает, сколько вытеснено; make lint, make test и make test-integration проходят.

**Граничные случаи:** max = 0 -> очистки, пометок и строк нет; очередь пуста -> trim вытесняет 0; источник удалён, а его посты в очереди -> trim и счётчики работают по source_id без падения (имя «удалённый источник #id»); в отчёте queue_limit не попадает в «отсеяно фильтрами».

**Тесты:** `tests/unit/test_bot_queue.py` — заполненность и 🔒 в строке, max = 0; `tests/unit/test_bot_status.py` — строка о заполненных источниках и её отсутствие; `tests/integration/test_daily_report.py` — queue_limited в воронке и по источникам, исключение из filtered; `tests/unit/test_daily_format.py` — строка воронки и строка под таблицей; `tests/unit/test_main.py` — QueueTrimComponent вызывает trim_queue на старте и пробрасывает ошибку (fake). Старые проверки не ослабляй, допустимо обновить только ожидания по `filtered`, если фикстуры содержали queue_limit.
