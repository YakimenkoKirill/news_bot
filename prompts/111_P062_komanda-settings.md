# Шаг 111 из 113 · P062 · Этап 19 — Настройки и эксплуатация

**Задача трекера:** Настройки без перезапуска
**Результат:** Команда /settings: просмотр и изменение ключевых параметров кнопками
**Коммит:** `feat(bot): команда /settings`
**Как запустить:** откройте репозиторий в Claude Code и напишите: «Выполни @prompts/111_P062_komanda-settings.md». После коммита: `python prompts/next_step.py --done`.

## Задача

1. **Обработчик** app/bot/handlers/settings.py:
   - `/settings` -> список параметров из RUNTIME_KEYS: человекочитаемое название, текущее значение, пометка «изменено» (если есть переопределение) и значение из yaml для сравнения.
   - Кнопка параметра -> подсказка с допустимыми значениями и FSM-состояние ожидания ввода; для min_score и score_decay_per_h — дополнительно кнопки-пресеты (например, 0.5 / 0.6 / 0.7), для quiet_hours — «Выключить».
   - Ввод -> RuntimeConfig.set; ошибка валидации -> текст ошибки и повторный запрос; успех -> обновлённый список.
   - «↩️ Как в конфиге» -> reset.
   - /cancel выходит из ввода.
2. **Клавиатуры и тексты:** SettingsAction(CallbackData, prefix="st") с полями action и key (ключ — короткий код, а не полное имя, чтобы уложиться в 64 байта; таблица соответствия в texts).
3. **COMMANDS:** `"settings": "параметры канала без перезапуска"` после "report".
4. **Один экран:** ответы идут через обычный message.answer — смена экрана работает автоматически (шаги 090–092).
5. **README.md:** раздел «Настройки на лету»: какие параметры, что значит «изменено», как вернуть значение из конфигурации.

**Критерий готовности:** Админ меняет тему канала, порог, интервал, тихие часы, лимит источника и коэффициент свежести из бота, и изменение действует без перезапуска.

**Граничные случаи:** Неверный ввод (буквы вместо числа, 25:00, порог 1.5) -> понятная ошибка, значение не меняется; два админа меняют один параметр -> побеждает последний, оба видят актуальное значение после действия; не-админ не видит /settings; длина callback_data ≤ 64 байт.

**Тесты:** `tests/unit/test_bot_settings.py` — список, ввод корректного и неверного значения для каждого типа, пресеты, reset, /cancel, длина callback_data; `tests/unit/test_bot_middleware.py` — отказ не-админу для /settings и st:...; `tests/unit/test_bot_common.py` — команда в меню.

**Контекст проекта:** Python 3.11+, aiogram 3.x. RuntimeConfig — шаг 110.

**Файлы:** app/bot/handlers/settings.py, app/bot/keyboards.py, app/bot/texts.py, app/bot/states.py, app/main.py, README.md, тестовые файлы из списка выше.

**Стиль проекта:** ruff, mypy strict, docstrings Google Style; инварианты — из CLAUDE.md.

**Ограничения:** Ни один модуль, кроме app/config.py, не читает os.environ. Токены и ключи — SecretStr (не попадают в repr и логи). Смена статуса новости — только через set_status и app/domain/status.py. Новые зависимости, заглушки (TODO, «...») и молчаливый except Exception: pass запрещены. Существующие тесты не ослабляй. Если меняется состав или порядок компонентов в app/main.py — обнови ожидания tests/unit/test_app_wiring.py; новая секция конфигурации должна быть описана в README.md (это проверяет tests/unit/test_readme.py).

**Формат ответа:** Полные файлы из списка «Файлы»; для README.md — новый или изменённый раздел целиком. Тесты обязательны; проверка: `make lint`, `make test`, `python -c "import app.main"`. Комментарии — только docstrings Google Style для сложных функций. После кода — таблица [Тест] -> [Критерий]. При нехватке данных сначала перечисли конкретные пробелы, значения не выдумывай (пороги и параметры — из configs/).
