## Автопилот: выполнение шагов из prompts/ по очереди

Когда человек пишет «Запусти автопилот», «Продолжай» или «Продолжи автопилот», выполняй шаги из каталога `prompts/` один за другим: каждый шаг — ровно один коммит, затем отправка в удалённый репозиторий и переход к следующему. Работай без вопросов, пока не сработает одно из условий остановки ниже.

### Цикл

1. Выполни `python prompts/next_step.py`. Он печатает следующий шаг и имя его файла. Если он пишет «Все шаги выполнены» — выведи итоговый отчёт и остановись.
2. Прочитай файл шага целиком инструментом Read. Читай его заново на каждом шаге, не полагайся на память о прошлых шагах: после сжатия контекста она неточна.
3. Выполни пункты 1–4 раздела «Порядок работы» из файла шага: проверка `git status`, сама задача, проверки, ровно один коммит с сообщением точно как в строке «Коммит» шага.
4. Пункт 5 («Остановись») в режиме автопилота означает конец шага, а не всей работы: выведи таблицу [Тест] -> [Критерий] и одной строкой, что осталось сделать человеку, затем продолжай.
5. Отметь шаг: `python prompts/next_step.py --done`. Скрипт сверяет последний коммит с коммитом шага и проверяет чистоту рабочего дерева.
6. Отправь коммит, если настроен удалённый репозиторий (`git remote get-url origin` завершается успешно): в первый раз `git push -u origin HEAD`, дальше `git push`. Если удалённого репозитория нет — пропусти отправку и упомяни это в итоговом отчёте.
7. Вернись к пункту 1.

Состояние автопилота хранится только в git: в истории коммитов и в `.git/next_step_progress.json`. Если контекст сжат или сессия начата заново — просто начни с пункта 1, ничего восстанавливать не нужно.

### Условия остановки

Остановись сразу, ничего не откатывая и не исправляя «на всякий случай», если:

- в начале шага `git status` показывает незакоммиченные изменения;
- шаг требует перечислить пробелы: нет ключа конфигурации с пометкой «задаёт человек», не хватает данных или файла;
- проверки (`make lint`, `make test`, команды из «Формата ответа») не проходят после трёх попыток исправления в рамках шага — в этом случае не коммить;
- `next_step.py --done` отказывается отметить шаг;
- `git push` отклонён (например, удалённая ветка ушла вперёд или нет прав);
- задача требует того, что может сделать только человек: секреты и токены, вход в Telegram-аккаунт, реальные данные, оплату, доступ к серверу;
- задача шага противоречит этому файлу или другому шагу.

### Запрещено

- `python prompts/next_step.py --done --force`, `git push --force`, `git commit --no-verify`, `git commit --amend` и `git rebase` для уже сделанных коммитов шагов;
- пропускать шаг, менять порядок шагов, объединять несколько шагов в один коммит или делить шаг на несколько коммитов;
- менять файлы в `prompts/` и раздел «Автопилот» этого файла;
- ослаблять или удалять тесты и критерии, чтобы проверки прошли;
- придумывать значения, которые шаг поручает задать человеку.

### Отчёт при остановке

Выведи кратко: какие шаги выполнены за этот запуск (номер и коммит), на каком шаге и по какой причине остановка, что конкретно нужно сделать человеку, и как продолжить: «после исправления напишите „Продолжай“».

### Подготовка (один раз, делает человек)

1. Положить `CLAUDE.md` и каталог `prompts/` в корень пустого репозитория.
2. `git init`, затем `git add -A && git commit -m "chore: промпты и автопилот"`.
3. По желанию подключить удалённый репозиторий: `git remote add origin <url>`.
4. Заполнить значения из раздела «Значения, которые нужно задать» в `prompts/README.md` до соответствующих шагов, либо дождаться остановки автопилота на них.
